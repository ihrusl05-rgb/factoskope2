# factoskope2

Django-сервис фактов и гороскопов.

## Общая страница импорта Excel

1. Войдите в `/admin/` и нажмите «Загрузить Excel».
2. На странице `/admin/content/import/` выберите «Факты» или «Гороскопы».
3. Выберите отдельный `.xlsx` размером до 5 МБ и нажмите «Импортировать».

Кнопки в списках фактов и гороскопов открывают эту же страницу. Факты и
гороскопы загружаются отдельными файлами; выбор типа задаёт обработчик.
Прежние адреса `/admin/content/fact/import/` и
`/admin/content/horoscope/import/` заменены общим адресом.

Факты импортируются таблицей на активном листе:

| Тип | Обязательные | Необязательные |
| --- | --- | --- |
| Факты | `Текст` | `Категория` |

У гороскопов формат другой. Первая строка листа содержит заголовок и дату
всех гороскопов файла, далее по одной строке на знак — название знака на
русском и текст:

| Знак зодиака | 22 сентября 2026 |
| --- | --- |
| Овен | Текст гороскопа |
| Телец | Текст гороскопа |

Дата в первой строке поддерживает формат `22 сентября 2026` и ISO
(`2026-09-22`). Одна ошибка даты останавливает весь импорт файла.

Правильные строки сохраняются сразу; ошибочные строки пропускаются и
показываются в отчёте с номером строки и причиной. Ошибка файла или заголовков
останавливает обработку до сохранения. Для импорта пользователь должен иметь
доступ к админке и права на создание и изменение выбранной модели.

### Сохранение фактов

`save_facts_database(file_path)` ищет существующий факт по тексту и обновляет
категорию. Пустая категория заменяется на `""`. Текст и категория очищаются
от пробелов по краям; пустой текст и категория длиннее 64 символов считаются
ошибками. Остальные поля существующего факта сохраняются. `ordering` из
Excel не читается: у новых записей он равен `0`, сортировка затем идёт по `id`.

### Сохранение гороскопов

`save_horoscopes_database(file_path)` ищет запись по дате и знаку и обновляет
текст. Новые и обновлённые гороскопы становятся черновиками. Снимите отметку
«Черновик» в админке после проверки, чтобы гороскопы появились в API.

### Единый отчёт

Обе функции сохранения вызывают `build_import_report` и возвращают словарь:

```python
{
    "Создано": 2,
    "Обновлено": 1,
    "Ошибки": [{"Строка": 5, "Причина": "Текст факта не может быть пустым"}],
}
```

«Обновлено» включает найденные записи даже при неизменном содержимом.
`import_completed` во view означает, что файл обработан: отдельные строки
могут содержать ошибки. Если правильных строк нет, страница сообщает, что
записи не сохранены.

## Общие части чтения Excel и форм

### Чтение строк

`read_excel_rows(file_path, required_columns)` открывает активный лист,
проверяет обязательные заголовки и собирает непустые строки в список.
Каждый элемент — пара из номера строки Excel и словаря с названиями колонок:

```python
[
    (2, {"Текст": "У осьминога три сердца.", "Категория": "Животные"}),
]
```

`file_path` — путь или файл из `request.FILES`. `required_columns` — набор
обязательных колонок; для фактов это `{"Текст"}`. Гороскопы читаются
отдельной функцией `parse_horoscop` со своим форматом листа. Заголовки
очищаются от пробелов по краям.

Внутри `read_excel_rows` вызывает `read_excel_sheet(file_path)`, которая
открывает книгу, возвращает все строки активного листа и закрывает файл.
Все строки читаются до `workbook.close()`: возвращается готовый список,
который можно использовать после закрытия файла. Это требует дополнительной
памяти для списка исходных строк.

Затем `parse_facts` преобразует русские заголовки
в поля модели и вызывает свою функцию нормализации. Ошибки сохраняют
исходные номера строк. Общая функция чтения ничего не записывает в базу.

### Общая форма загрузки

`ExcelImportForm` содержит поле `file` и метод `clean_file`: проверяет `.xlsx`
и размер до 5 МБ. `ContentImportForm` наследует эти правила и добавляет выбор `content_type`:
`facts` (факты) или `horoscopes` (гороскопы).

При `form.is_valid()` Django вызывает `clean_file`. Подходящий файл попадает
в `form.cleaned_data["file"]`, а ошибка отображается возле поля загрузки.
Метод формы проверяет расширение и размер; структуру Excel проверяет
`read_excel_sheet`/`read_excel_rows`, а значения ячеек — `normalize_fact`
и `parse_horoscop`.

## Как связана общая страница импорта

`ContentAdminConfig` в `INSTALLED_APPS` выбирает `ContentAdminSite` вместо
стандартного класса административного сайта. Обычные страницы Django admin
сохраняются благодаря наследованию от `AdminSite`. Метод `get_urls` добавляет
маршрут `content/import/` с именем `admin:content_import`.

`import_content_view` получает `ContentImportForm`. После `is_valid()` тип и
файл находятся в `cleaned_data`. По типу выбирается `save_facts_database`
или `save_horoscopes_database`. Её результат передаётся в шаблон
`import_content.html` под ключом `report`. Заголовки отчёта и ошибки выводятся
одинаково для обоих типов. Два старых обработчика и шаблона заменены общими.

## Получение гороскопов через API

`HoroscopeAPIView` выбирает активные гороскопы без отметки «Черновик» на
запрошенную дату. `values_list("sign", "text")` получает пары «код знака — текст»
одним запросом; `dict(...)` собирает из них словарь. Затем цикл по `ZodiacSign`
строит ответ из этого словаря. Русские названия знаков и `null` для отсутствующих
записей сохраняются. Обращений к базе внутри этого цикла нет.
